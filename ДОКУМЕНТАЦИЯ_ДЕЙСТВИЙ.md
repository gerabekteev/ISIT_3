**Найденные проблемы и их решения:**

1. **Опечатка в методичке**: ссылка на библиотеку дана как `plantuml-stdlib/C4PlantUML` (без дефиса) — GitHub отдаёт 404. Правильный путь: `plantuml-stdlib/C4-PlantUML` (с дефисом). Исправлено в md-файлах лаб1; сами диаграммы должны подключать библиотеку с дефисом.
2. **Конфликт портов**: хост-порт 8080 занят сторонним Apache `httpd.exe` (PID 6944, приветственная страница с логотипом EDB), из-за чего контейнер PlantUML Server не мог опубликовать порт и все проверки «упирались» в чужой httpd. 3. **Свежий тег `jetty` образа plantuml-server** имеет переработанную структуру путей (классический `/png/<код>` не работает) — образ закреплён за `jetty-v1.2023.10`, идентичной версии jar из методички.
4. Относительный путь у `plantuml.jar -o` считается **от папки исходника**, а не от cwd — в `start_lab.bat` используется абсолютный путь.

- `java -jar tools/plantuml.jar -png ...` + Graphviz → `лаб1/diagrams/png/тест_инструментов.png` ✅
