Практически освоить концепцию Diagrams-as-Code в командном масштабе: интегрировать статические и динамические модели C4, созданные на предыдущих этапах всеми участниками команды, в единый Git-репозиторий с модульной структурой; развернуть пайплайн непрерывной интеграции (CI/CD) для автоматической валидации синтаксиса PlantUML и генерации графической документации; освоить командный цикл интеграции наработок через ветвление, Pull Requests и Code Review с контролем единого глоссария идентификаторов.

## 5. CI/CD-пайплайн

Пайплайн `.github/workflows/render-docs.yml` запускается при каждом Push в `main` и при каждом Pull Request. К стандартным шагам методики (Java, Graphviz, PlantUML 1.2023.10, компиляция в PNG, коммит артефактов ботом) добавлены: шаг линтинга запретов методики (сборка падает с «Красным крестом» при использовании запрещённых макросов позиционирования), блок `permissions: contents: write` (право бота на коммит артефактов) и абсолютный путь выгрузки `$GITHUB_WORKSPACE/docs/images` — относительный `-o` у PlantUML отсчитывается от каталога каждого исходника, из-за чего артефакты из вложенных папок не попадали бы в базу знаний:

```yaml
permissions:
  contents: write

jobs:
  validate-and-render:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository code
        uses: actions/checkout@v4
      - name: Setup Java Environment
        uses: actions/setup-java@v4
        with: { distribution: 'temurin', java-version: '11' }
      - name: Install Graphviz Engine
        run: sudo apt-get install -y graphviz
      - name: Download PlantUML Jar Executable
        run: wget .../plantuml-1.2023.10.jar -O plantuml.jar
      - name: Lint: enforce methodologist rules (banned macros)
        run: |
          set -e
          if grep -rnE "Rel_(R|L|D|U)\(" src/ ; then
            echo "❌ CRITICAL FAILURE: banned macro Rel_R/Rel_L/Rel_D/Rel_U found."
            echo "Use standard 'Rel()' macro per methodologist guidelines."
            exit 1
          fi
      - name: Validate Syntax and Compile Diagrams to PNG
        run: java -jar plantuml.jar -charset UTF-8 -verbose -png
             -o "$GITHUB_WORKSPACE/docs/images" "src/**/*.puml"
      - name: Commit and Push Rendered Artifacts
        if: github.event_name == 'push'
        run: git add docs/images/*.png && git commit -m 'docs: auto-update...' && git push
```

Для локального воспроизведения шагов пайплайна создан скрипт `ci_local_build.sh` — те же шесть шагов, тексты линтера идентичны YAML. Пайплайн настроен для запуска в GitHub Actions при размещении репозитория на хостинге; в рамках работы его шаги воспроизведены локальной эмуляцией (логи в п. 7).

### 7.2. Падение сборки при нарушении запретов (❌)

Проверка срабатывания «Красного креста»: в ветке `demo/syntax-violation` (PR №5) была предпринята попытка использовать запрещённый макрос жёсткого позиционирования `Rel_D` в файле `src/components/backend_components.puml`. Линтер пайплайна (шаг 5) остановил сборку до этапа компиляции:

```text

❌ CRITICAL FAILURE: banned macro Rel_R/Rel_L/Rel_D/Rel_U found.
Use standard 'Rel()' macro per methodologist guidelines.
----> Pipeline failed. Status: CRITICAL FAILURE ❌
```

Замечание внесено в протокол Code Review (`reviews/PR5_syntax_violation.md`), автор заменил макрос на стандартный `Rel()`, повторный прогон — `SUCCESS ✅`, исправление вошло в `main` через PR №5. Полный командный цикл «нарушение → красная сборка → Code Review → исправление → зелёная сборка» воспроизведён на живом репозитории.

В ходе лабораторной работы завершён полный цикл архитектурного проектирования системы DemoScope в составе команды 18 (Бектеев Г.А., Алибеков А., Слисаренко Д., Лиджиев Э.С., Сырлыбаев Б.С.). Статические и динамические модели всех уровней C4 (L0–L4 для серверной и клиентской частей, динамика, развертывание) интегрированы в единый Git-репозиторий с модульной структурой; архитектура оформлена по принципу Diagrams-as-Code — диаграммы версионируются вместе с кодом и автоматически перерисовываются. Развернут CI/CD-пайплайн валидации и рендеринга: линтер запретов методики и компилятор PlantUML, генерирующий 11 растровых артефактов в базу знаний. Командная интеграция выполнена через пять Pull Request с Code Review Тимлида (протоколы замечаний зафиксированы в репозитории); на живом репозитории воспроизведён полный цикл обработки нарушения — падение сборки с «Красным крестом», исправление по замечанию ревьюера, повторная зелёная сборка. Полученная инфраструктура обеспечивает сопровождение архитектурного описания проекта на последующих спринтах разработки.
